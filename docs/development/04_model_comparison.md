# 04. Ollama Cloud LLM 모델 비교 및 경영자문 Agent 테스트 결과

## 1. 개요

### 1.1 테스트 목적

본 문서는 캡스톤 프로젝트의 경영자문(Advisory) Agent에 적용할 LLM 모델을 비교하고, 기존 M&A 평가 및 What-if 시나리오 기능의 정상 작동 여부를 검증한 결과를 기록한다.

테스트 대상 모델은 다음과 같다.

- `gpt-oss:20b-cloud`
- `gemma4:31b-cloud`

두 모델 모두 Ollama Cloud API를 통해 실행하였으며, 실제 경영자문 Agent 환경에서 Tool Calling 정확도, 응답 품질, 예외 처리 및 안정성을 확인하였다.

### 1.2 테스트 범위

- CEO, CFO, CTO 관점의 기본 M&A 평가
- 인수가격 및 영업이익률 변경 시나리오
- 고객 매출 의존도 변경 시나리오
- 복합 What-if 시나리오
- 경영진 회의 맥락(Context) 전달
- 존재하지 않는 기업 처리
- 잘못된 입력값 처리
- Python 자동 테스트 실행

본 테스트는 경영자문 Agent의 1차 기능 검증을 목적으로 하며, Super Agent 연동과 Open WebUI 기반 전체 시스템 통합 테스트는 포함하지 않는다.

| 담당 기능 | 경영자문 Agent |
| LLM 제공 방식 | Ollama Cloud API |

| 자동 테스트 | pytest |
| 테스트 대상 기업 | 뉴로엣지, 테스트기업XYZ |

### 2.1 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/runtime/llm.py` | Ollama LLM 초기화 및 연결 |
| `backend/app/systems/k_electronics/agents/advisory.py` | 경영자문 Agent 실행 |
| `backend/app/runtime/agent_core.py` | Agent 실행 및 Tool 호출 검증 |
| `backend/app/library/tools/run_mna_review.py` | M&A 평가 Tool |
| `backend/app/library/workflows/mna_review.py` | M&A 평가 Workflow |
| `backend/app/library/workflows/mna_scenario.py` | What-if 시나리오 Workflow |
| `backend/app/library/skills/mna_feasibility_review.py` | M&A 평가 관련 Skill 지침 |
| `backend/tests/test_mna_review_workflow.py` | M&A 평가 자동 테스트 |
| `backend/tests/test_mna_scenario.py` | What-if 자동 테스트 |

### 2.2 LLM 환경변수

모델 전환은 `backend/.env`의 `OLLAMA_MODEL` 값을 변경하는 방식으로 진행하였다.

```dotenv
LLM_PROVIDER=ollama
OLLAMA_MODEL=gpt-oss:20b-cloud
OLLAMA_BASE_URL=https://ollama.com
```

Gemma 테스트에서는 다음과 같이 변경하였다.

```dotenv
OLLAMA_MODEL=gemma4:31b-cloud
```

`OLLAMA_API_KEY`는 별도로 설정하며, 보안상 문서와 GitHub에 기록하지 않는다.

## 3. 기본 M&A 평가 테스트

### 3.1 테스트 목적

기존 경영자문 Agent가 기업 데이터를 기반으로 M&A 타당성을 분석하고, CEO·CFO·CTO 관점에 따라 서로 다른 평가 요소를 강조하는지 확인하였다.

### 3.2 테스트 기업: 뉴로엣지

테스트에서 사용한 주요 기업 정보는 다음과 같다.

| 항목 | 값 |
|---|---|
| 기업명 | 뉴로엣지 |
| 기존 인수 희망가격 | 2.8조 원 |
| 적정가치 상단 | 2.3조 원 |
| 영업이익률 | -8.2% |
| 3년 매출 CAGR | 31% |
| 주요 고객 매출 비중 | 46% |
| 주요 위험 | 핵심인력 이탈, 특허소송, 고객 의존도 |

### 3.3 CFO 관점

재무적 타당성을 중심으로 다음 요소를 확인하였다.

- 인수 희망가격과 적정 기업가치의 차이
- 영업이익률 및 수익성
- 고객 매출 집중도
- 인수가격 협상 필요성
- 재무적 위험 요소

확인된 주요 결과:

- 인수 희망가격 2.8조 원
- 적정가치 상단 2.3조 원
- 적정가치 상단 대비 약 21.7% 프리미엄
- 영업이익률 -8.2%
- 주요 고객 매출 비중 46%
- 최종 권고: `CONDITIONAL_PROCEED`

### 3.4 CTO 관점

기술적 타당성을 중심으로 다음 요소를 확인하였다.

- NPU 관련 핵심 기술 경쟁력
- 자체 개발 대비 기술 확보 기간 단축
- 핵심 설계인력 유지
- 특허소송 위험
- 기술 통합 가능성

확인된 주요 결과:

- 자체 개발 예상 기간: 36~48개월
- 인수 후 통합 예상 기간: 12~18개월
- 예상 기간 단축: 24~30개월
- 핵심 설계인력 유지가 중요한 조건으로 제시됨
- 특허소송 및 기술 통합 위험 검토
- 최종 권고: `CONDITIONAL_PROCEED`

### 3.5 CEO 관점

전략적 관점에서 다음 요소를 확인하였다.

- 사업 전략과의 적합성
- 시장 진입 기간 단축
- 기업 성장성
- 인수 시너지
- 주요 경영 위험

확인된 주요 결과:

- 전략적 적합성 및 성장성 검토
- 3년 매출 CAGR 31% 반영
- 인수 후 시장 진입 기간 단축 가능성 반영
- 인수가격, 인력, 특허, 고객 의존도 위험 고려
- 최종 권고: `CONDITIONAL_PROCEED`

### 3.6 평가

CEO·CFO·CTO 관점의 기본 M&A 평가에서 각 Persona의 특성에 맞는 분석 내용이 확인되었다.

다만 현재까지는 개별 Persona 응답을 중심으로 검증하였다. 세 Persona의 평가 결과를 하나의 종합 보고서로 통합하는 기능은 별도 개발 대상이다.

## 4. What-if 시나리오 테스트

### 4.1 테스트 목적

인수가격, 영업이익률, 고객 집중도 등 주요 변수를 변경했을 때 기존 기업 데이터와 변경된 시나리오를 비교하고 평가 결과가 적절하게 달라지는지 확인하였다.

GPT-OSS와 Gemma에서 동일한 시나리오를 실행하여 Tool Calling 인자와 최종 응답을 비교하였다.

### 4.2 시나리오 1: 인수가격 및 영업이익률 개선

**테스트 조건**

| 항목 | 기존값 | 변경값 |
|---|---|---|
| 인수가격 | 2.8조 원 | 2.2조 원 |
| 영업이익률 | -8.2% | 5% |
| Persona | CFO | CFO |

**결과**

- 두 모델 모두 `asking_trillion_krw=2.2`를 전달하였다.
- 두 모델 모두 `operating_margin=0.05`를 전달하였다.
- 인수가격 인하에 따라 밸류에이션 부담이 완화되었다.
- 영업이익률 개선에 따라 수익성 평가가 긍정적으로 변경되었다.
- 특허소송 및 고객 의존도 등의 잔여 위험은 유지되었다.
- 최종 권고는 `CONDITIONAL_PROCEED`로 유지되었다.

**판정:** 두 모델 모두 주요 입력값 전달 및 시나리오 응답 성공.

### 4.3 시나리오 2: 고객 매출 의존도 완화

**테스트 조건**

| 항목 | 기존값 | 변경값 |
|---|---|---|
| 최대 고객 매출 비중 | 46% | 25% |
| Persona | CEO | CEO |

**결과**

- 두 모델 모두 `revenue_share=0.25`를 전달하였다.
- 고객 집중 위험 등급이 `HIGH`에서 `MEDIUM`으로 변경되었다.
- 주요 위험 항목 수가 3개에서 2개로 감소하는 결과가 확인되었다.
- 인수가격 및 영업이익률 변경 인자는 전달하지 않았다.
- 최종 권고는 `CONDITIONAL_PROCEED`로 유지되었다.

**판정:** 두 모델 모두 정상.

### 4.4 시나리오 3: 복합 변수 변경

**테스트 조건**

| 항목 | 기존값 | 변경값 |
|---|---|---|
| 인수가격 | 2.8조 원 | 2.5조 원 |
| 영업이익률 | -8.2% | -10% |
| 최대 고객 매출 비중 | 46% | 60% |
| Persona | CFO | CFO |

**Tool Calling 결과**

두 모델 모두 다음 인자를 올바르게 전달하였다.

```python
asking_trillion_krw = 2.5
operating_margin = -0.1
revenue_share = 0.6
```

**평가 결과**

- 인수가격이 2.8조 원에서 2.5조 원으로 낮아지면서 밸류에이션 부담은 완화되었다.
- 적정가치 상단 대비 프리미엄은 약 21.7%에서 약 8.7%로 낮아졌다.
- 밸류에이션 위험 등급은 `HIGH`에서 `MEDIUM`으로 개선되었다.
- 영업이익률은 -8.2%에서 -10%로 악화되었다.
- 고객 집중도는 46%에서 60%로 악화되었다.
- 영업이익률 및 고객 집중도의 위험 등급은 기존 등급을 유지하였다.
- 최종 권고는 `CONDITIONAL_PROCEED`로 유지되었다.

**모델 간 차이**

- GPT-OSS는 일부 평가 항목에서 위험 등급의 변화가 없다는 점을 중심으로 설명하였다.
- Gemma는 위험 등급이 동일하더라도 실제 수치가 악화되었다는 점을 더 명확하게 설명하였다.

이는 해당 실행에서 관찰된 응답 표현 차이이며, 일반적인 모델 우열을 확정하는 근거는 아니다.

**판정:** 두 모델 모두 Tool Calling 및 최종 응답 성공.

### 4.5 What-if 테스트 종합

|---|---|---|
| 인수가격 변경 인식 | 성공 | 성공 |
| 영업이익률 변경 인식 | 성공 | 성공 |
| 고객 집중도 변경 인식 | 성공 | 성공 |
| 복합 변수 전달 | 성공 | 성공 |
| 변경 전후 비교 | 확인 | 확인 |
| 최종 권고 생성 | 성공 | 성공 |

총 3개 시나리오에서 두 모델 모두 기대한 주요 Tool Calling 인자를 전달하였다.

## 5. 회의 맥락(Context) 전달 테스트

### 5.1 테스트 목적

경영진 회의에서 결정된 인수가격 상한 및 위험 요소가 M&A 평가 Tool에 올바르게 전달되는지 확인하였다.

특히 인수가격 상한과 실제 인수가격 변경 시나리오가 혼동되지 않는지 중점적으로 검증하였다.

### 5.2 테스트 질문

> 뉴로엣지 인수 타당성을 CFO 관점에서 평가해 줘. 경영진 회의에서 인수가격 상한은 2.5조 원 이하로 정했고, 핵심 설계팀 이탈 위험과 코어NPU 특허소송 위험을 확인했어. 이 회의 기준을 반영해 줘.

### 5.3 Gemma 결과

확인된 Tool 호출:

```python
{
    "name": "run_mna_review",
    "args": {
        "company": "뉴로엣지",
        "persona": "CFO",
        "query": "뉴로엣지 인수 타당성을 CFO 관점에서 평가해 줘.",
        "context": (
            "경영진 회의에서 인수가격 상한은 2.5조 원 이하로 정했고, "
            "핵심 설계팀 이탈 위험과 코어NPU 특허소송 위험을 확인했음."
        )
    }
}
```

확인 사항:

- `run_mna_review` 호출 성공
- CFO Persona 전달
- 경영진 회의 내용이 `context`에 포함됨
- 인수가격 상한이 What-if 인수가격으로 잘못 전달되지 않음

### 5.4 GPT-OSS 결과

확인된 Tool 호출 인자:

```python
{
    "asking_trillion_krw": None,
    "company": "뉴로엣지",
    "context": (
        "경영진 회의에서 인수가격 상한은 2.5조 원 이하로 정했고, "
        "핵심 설계팀 이탈 위험과 코어NPU 특허소송 위험을 확인했어."
    ),
    "operating_margin": None,
    "persona": "CFO",
    "query": "뉴로엣지 인수 타당성을 CFO 관점에서 평가해 줘.",
    "revenue_share": None
}
```

확인 사항:

- `run_mna_review` 호출 성공
- CFO Persona 전달
- `context` 정상 전달
- `asking_trillion_krw=None`
- `operating_margin=None`
- `revenue_share=None`

### 5.5 종합 결과

| 검증 항목 | GPT-OSS | Gemma |
|---|---|---|
| Tool 호출 | 성공 | 성공 |
| 기업명 전달 | 성공 | 성공 |
| Persona 전달 | 성공 | 성공 |
| 가격 상한 전달 | 성공 | 성공 |
| 핵심인력 위험 전달 | 성공 | 성공 |
| 특허소송 위험 전달 | 성공 | 성공 |
| 가격 상한과 What-if 구분 | 성공 | 성공 |

**결론:** 두 모델 모두 회의 맥락을 올바른 Tool 인자로 전달하였다.

단, Tool 호출 인자를 직접 검사한 결과와 실제 Workflow 내부의 맥락 반영 정확성은 구분하여 해석해야 한다.

## 6. 존재하지 않는 기업 처리 테스트

### 6.1 테스트 목적

기업 데이터가 등록되어 있지 않은 경우, LLM이 재무정보를 임의로 생성하지 않고 데이터 부족을 안내하는지 확인하였다.

테스트 대상 기업명은 `테스트기업XYZ`이다.

### 6.2 Gemma 테스트

테스트 질문:

> 존재하지 않는 가상의 기업 테스트기업XYZ의 인수 타당성을 CFO 관점에서 평가해 줘.

확인된 응답:

> 대상 기업인 테스트기업XYZ에 대한 데이터가 등록되어 있지 않아 재무적 타당성 평가를 수행할 수 없습니다. 데이터가 없는 기업에 대해서는 추측하여 보고하지 않는 것이 원칙이므로, 분석 대상 기업의 정확한 명칭을 확인해 주시기 바랍니다.

**결과**

- 데이터 부재 안내 성공
- 임의 재무정보 생성 없음
- 추가 기업명 확인 요청

**판정:** 최종 응답 정상.

최초 실행에서는 최종 응답을 확인하였으며, 이후 별도 Tool Calling 테스트에서도 정상 호출을 확인하였다.

### 6.3 GPT-OSS 첫 번째 테스트: Tool Calling 실패

**테스트 목적**

**테스트 질문**

> 존재하지 않는 가상의 기업 테스트기업XYZ의 인수 타당성을 CFO 관점에서 평가해 줘.

- 정확한 모델 내부 판단 원인은 확인할 수 없다.

- **균형 잡힌 시나리오 분석:** 인수가격 인하로 밸류에이션 부담이 완화되는 긍정적 변화와 수익성 및 고객 집중도 악화라는 부정적 변화를 구분하여 제시하였다.
- **예외 상황에 대한 적절한 응답:** 존재하지 않는 기업에 대해 재무정보를 임의로 생성하지 않고 데이터 부재 및 평가 불가능 사유를 안내하였다.
- **경영진 의사결정 지원:** 위험 등급뿐 아니라 변경된 수치와 잔여 위험을 설명하여, 시나리오 변화가 인수 판단에 갖는 의미를 이해하는 데 도움이 되었다.

**아쉬운 점**

- **정량적인 성능 검증 부족:** 현재까지 주요 테스트에서 별도의 기능 오류가 확인되지 않았으나, 반복 호출 성공률 및 응답 속도에 대한 정량적 검증은 진행하지 않았다.
- **제한된 시나리오 검증:** 특정 기업과 일부 M&A 시나리오를 중심으로 테스트하였으므로, 다양한 기업 데이터와 복잡한 요청에서도 동일한 응답 품질을 유지하는지는 추가 확인이 필요하다.

**종합 평가**

Gemma 31B는 주요 Tool Calling 기능을 정상적으로 수행하면서도, 복합 What-if 시나리오에서 재무 수치의 변화와 위험 등급의 의미를 비교적 상세하게 설명하였다.

특히 긍정적 변화와 부정적 변화를 동시에 고려하여 결과를 제시한 점에서, 경영진의 의사결정을 지원하는 경영자문 Agent의 목적에 더 부합하는 응답을 제공하였다.

### 10.3 모델별 주요 평가 항목 비교

### 10.4 우선 적용 모델 선정: Gemma 31B

**현재 테스트 결과를 기준으로 경영자문 Agent의 우선 적용 모델은 `gemma4:31b-cloud`로 잠정 선정한다.**

**선정 근거**

1. **더 구체적인 위험 분석:** Gemma는 위험 등급이 유지되더라도 실제 재무 수치가 악화되는 상황을 명확하게 설명하였다.
2. **균형 있는 의사결정 지원:** 복합 시나리오에서 인수가격 하락에 따른 긍정적 효과와 수익성·고객 집중도 악화에 따른 부정적 효과를 구분하여 제시하였다.
3. **주요 기능의 정상 작동:** What-if 분석, Context 전달 및 존재하지 않는 기업 처리 등 핵심 기능에서 정상 동작을 확인하였다.
4. **경영자문 Agent 목적과의 적합성:** 경영진 의사결정 지원에서는 단순한 위험 등급의 변화뿐 아니라 재무 수치와 위험의 의미를 정확하게 전달하는 것이 중요하며, 이번 테스트에서는 Gemma가 해당 부분에서 더 우수한 응답을 제공하였다.

### 10.5 선정 결과의 한계 및 향후 재평가

이번 모델 선정은 2026년 11월 3일까지 수행한 제한된 테스트 결과를 기준으로 한 잠정적인 판단이다.

두 모델 모두 핵심 기능에서 정상 작동하였으며, 현재 확인된 응답 품질 차이가 모든 M&A 시나리오에서 동일하게 나타난다고 단정할 수는 없다.

또한 응답 속도, 반복 실행 안정성, API 사용량 및 향후 로컬 GPU 서버에서의 구동 성능은 충분히 비교되지 않았다.

향후 다음 항목을 추가 검증할 예정이다.

- 동일 시나리오 반복 실행을 통한 Tool Calling 성공률 비교
- 응답 시간 및 안정성 측정
- 다양한 기업 데이터에 대한 평가 품질 비교
- CEO·CFO·CTO 종합 평가 기능에서의 응답 품질 확인
- 로컬 GPU 서버 환경에서의 모델 구동 가능성 및 성능 검증

**최종 판단**

현재 경영자문 Agent에 필요한 핵심 Tool Calling 기능은 두 모델 모두 주요 테스트에서 정상적으로 수행하였다.

그러나 복합적인 재무 위험을 해석하고 경영진에게 설명하는 능력에서는 이번 테스트에서 Gemma 31B가 상대적으로 더 우수한 결과를 보였다.

따라서 현 단계에서는 **Gemma 31B를 우선 적용 모델로 잠정 선정하고, GPT-OSS 20B는 비교 및 대체 모델로 유지**하는 것이 적절하다고 판단한다.

단, 향후 추가 테스트에서 응답 속도, 안정성 또는 로컬 구동 성능에 유의미한 차이가 확인되면 선정 모델을 변경할 수 있다.
