# 01. M&A 경영자문 Agent Workflow 분석

**프로젝트:** C-Level 경영지원 AI 멀티 에이전트  
**담당 기능:** M&A 경영자문 Agent Workflow 확장  

---

## 1. 분석 목적

기존 M&A 경영자문 Agent의 구조와 데이터 처리 과정을 파악하고, 향후 2~3주 동안 확장할 기능 및 수정이 필요한 코드를 식별한다.

기존 Agent와 Workflow Tool을 최대한 재활용하여 인수가격 변경, 위험 조건 변화, 경영자 Persona 종합 평가 기능을 구현하는 것을 목표로 한다.

본 문서는 기존 M&A 경영자문 Workflow의 구조와 개선 이전의 평가 로직을 분석한 결과이다. 이후 진행한 평가 로직 수정 및 검증 결과는 `02_evaluation_fix.md`에 별도로 정리하였다.

## 2. 기존 시스템 구조

현재 시스템은 LangGraph 기반 AI Agent와 규칙 기반 M&A 평가 Workflow로 구성되어 있다.

### 전체 처리 흐름

1. 사용자가 M&A 타당성 검토를 요청한다.
2. 경영자문 Agent가 요청을 분석한다.
3. 필요에 따라 `run_mna_review` Tool을 호출한다.
4. Workflow가 기업 데이터를 조회한다.
5. CEO·CFO·CTO 중 선택된 관점에 따라 평가 항목을 정렬한다.
6. 재무·전략·기술·리스크 항목을 평가한다.
7. 인수 권고와 주요 조건을 생성한다.
8. Agent가 Workflow 결과를 기반으로 최종 답변을 생성한다.

슈퍼 Agent를 통해 요청한 경우에는 다른 전문 Agent에서 전달된 회의·뉴스 정보를 검토 맥락으로 활용할 수 있다.

## 3. 주요 코드 분석

모든 파일 경로는 `backend/` 기준이다.

| 파일 | 주요 역할 |
|---|---|
| `app/systems/group/agents/advisory.py` | 경영자문 Agent 정의 및 실행 |
| `app/library/skills/mna_feasibility_review.py` | M&A 분석을 위한 Agent 지침 |
| `app/library/tools/run_mna_review.py` | M&A 평가 Workflow 호출 |
| `app/library/workflows/mna_review.py` | 실제 평가 및 인수 권고 생성 |
| `app/systems/group/data/companies.json` | 그룹 M&A 분석용 기업 정보 |
| `tests/test_mna_review_workflow.py` | 기존 평가 로직 검증 |

### 3.1 핵심 Workflow 함수

| 함수 | 기능 |
|---|---|
| `load_companies()` | 기업 JSON 데이터 로드 |
| `find_company()` | 기업명 및 별칭으로 기업 조회 |
| `resolve_persona()` | CEO·CFO·CTO 평가 관점 선택 |
| `extract_context_signals()` | 회의·뉴스 맥락에서 주요 조건 추출 |
| `summarize_inputs()` | 평가 입력 데이터 정리 |
| `evaluate_all()` | 평가 항목별 결과 생성 |
| `recommend()` | 종합 인수 권고 결정 |
| `review_acquisition()` | 전체 M&A 평가 Workflow 실행 |

## 4. 기존 M&A 평가 기능

### 4.1 평가 항목

- 전략적 적합성
- 시장 진입 시간 단축
- 사업 추진 가치
- 인수가격 적정성
- 수익성
- 고객 집중도
- 재무적 위험
- 거래 조건
- 기술 적합성
- 핵심 기술인력 유지
- 특허 및 지식재산권 위험
- 기술 통합 가능성
- 위험과 기회의 균형

### 4.2 Persona별 분석

**CEO**
- 전략적 적합성
- 시장 진입 가능성
- 사업 가치
- 위험과 기회의 균형

**CFO**
- 인수가격 적정성
- 수익성
- 고객 집중도
- 재무 위험
- 거래 조건

**CTO**
- 기술 적합성
- 시장 진입 시간
- 핵심 기술인력 유지
- 특허 위험
- 기술 통합

현재 코드는 모든 관점에서 전체 평가 항목을 계산하며, Persona에 따라 주요 항목의 우선순위와 설명을 다르게 제공한다.

동일한 기업 데이터에 대한 최종 인수 권고는 Persona와 관계없이 동일하게 산출된다.

## 5. 기존 데이터 구조

현재 데모는 JSON 파일에 저장된 가상 기업 정보를 사용한다.

### 그룹 시스템: 브라이트셀

- 사업 분야: 배터리 양극재 소재
- 2025년 매출액: 9,800억 원
- 3년 매출 CAGR: 22%
- 영업이익률: +6.1%
- 요구 인수가격: 1.6조 원
- 적정가치 추정 범위: 1.3~1.5조 원
- 최대 고객 매출 비중: 52%
- 진행 중인 특허 분쟁: 없음

### K전자 시스템: 뉴로엣지

- 사업 분야: AI NPU 설계
- 2025년 매출액: 4,200억 원
- 3년 매출 CAGR: 31%
- 영업이익률: -8.2%
- 요구 인수가격: 2.8조 원
- 적정가치 추정 범위: 2.0~2.3조 원
- 최대 고객 매출 비중: 46%
- 특허 분쟁: 코어NPU 관련 소송

두 기업 모두 가상 데이터이므로 실제 기업의 재무·시장 정보로 해석하지 않는다.

## 6. 기존 코드의 문제점

### 6.1 수익성 평가 오류

`_profitability()`는 영업이익률과 관계없이 적자 기업이라는 판단을 생성한다.

따라서 브라이트셀처럼 영업이익률이 양수인 기업에 대해 잘못된 설명이 발생할 수 있다.

**개선 방향:** 영업이익률을 기준으로 흑자·적자·손익분기 상태를 구분한다.

### 6.2 특허 분쟁 평가 오류

`_ip_risk()`는 기업 데이터에 분쟁이 없다고 표시되어 있어도 특허 분쟁 관련 위험을 생성한다.

**개선 방향:** 실제 분쟁 여부에 따라 위험 평가와 설명을 분기한다.

### 6.3 재무적 위험 평가의 고정 문구

`_financial_downside()`는 고객 이탈, 특허소송, 적자 지속을 동시에 가정한다.

**개선 방향:** 기업별로 확인된 위험 요소를 조합하여 평가한다.

### 6.4 시나리오 분석 부족

현재는 JSON에 저장된 인수가격을 기준으로 평가한다.

사용자가 인수가격이나 위험 조건을 변경하여 결과를 비교하는 기능이 부족하다.

**개선 방향:** 사용자가 제공한 가정값을 평가에 반영하고 기본 시나리오와 비교한다.

### 6.5 Persona 종합 분석 부족

CEO·CFO·CTO의 평가 항목별 우선순위는 구분되지만, 세 관점의 주요 판단을 통합한 결과를 제공하는 Workflow는 부족하다.

**개선 방향:** 기존 평가 결과를 재사용하여 관점별 핵심 근거, 공통 위험, 최종 권고를 정리한다.

## 7. Workflow 확장 방향

### 1단계: 기존 평가 정확도 개선

- 수익성 평가 분기
- 특허 분쟁 위험 평가 분기
- 재무적 위험 평가 개선
- 기존 기능 회귀 테스트

### 2단계: M&A What-if 시나리오

- 인수가격 변경
- 고객 의존도 변경
- 수익성 변화 가정
- 시나리오별 재평가
- 변경 전후 결과 비교

### 3단계: 경영진 Persona 통합

- CEO 전략적 관점 요약
- CFO 재무적 관점 요약
- CTO 기술적 관점 요약
- 공통 위험 및 인수 조건 통합

### 4단계: 테스트 및 시스템 연동

- 기존 평가 기능 검증
- 신규 시나리오 테스트
- Agent Tool 연동
- Super Agent 호출 검증
- 최종 시연 결과 정리

## 8. 테스트 현황 및 제한사항

기존 저장소에는 뉴로엣지 M&A 평가를 검증하는 테스트 코드가 구현되어 있다.

현재 분석은 코드와 기업 데이터의 정적 분석을 기반으로 한다.

별도로 작성한 1차 평가 정확도 개선안이 있으나, 아직 해당 변경안이 GitHub 브랜치에 반영되었다고 볼 수 없다.

전체 프로젝트의 회귀 테스트 및 실제 LangGraph Agent 통합 실행은 별도 검증이 필요하다.

## 9. 분석 결과

기존 M&A 경영자문 Agent는 LangGraph, Tool, Workflow가 분리된 구조를 갖추고 있어 기능 확장에 적합하다.

따라서 신규 Agent를 처음부터 구축하기보다 기존 M&A 평가 Workflow의 오류를 개선하고, 조건 변경에 따른 시나리오 분석 및 Persona 통합 평가 기능을 추가하는 것이 효율적이다.
