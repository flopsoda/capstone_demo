# 02. M&A 평가 로직 개선 및 검증

**프로젝트:** C-Level 경영지원 AI 멀티 에이전트  
**담당 분야:** 경영자문 Agent  
**주요 개발 내용:** 기업별 수익성·특허 분쟁·재무 위험 평가 로직 개선, 사업 가치 평가 문구 수정, 핵심인력 및 인수 거래 조건의 기업별 맞춤화, 자동 테스트 18개 및 M&A Workflow 검증   
**작성일:** 2026-11-01

## 1. 개발 목적

기존 M&A 경영자문 Workflow는 뉴로엣지처럼 영업적자와 특허 분쟁이 존재하는 기업을 기준으로 일부 평가 로직이 작성되어 있었다.

그 결과 브라이트셀처럼 흑자이고 진행 중인 특허 분쟁이 없는 기업에서도 잘못된 위험 평가와 거래 조건이 출력되는 문제가 발생했다.

이번 개발에서는 기존 경영자문 Agent 구조를 유지하면서 기업별 실제 데이터를 반영하도록 평가 함수 6개를 수정했다.

## 2. 주요 수정 사항

| 수정 함수 | 기존 문제 | 개선 내용 |
|---|---|---|
| `_profitability()` | 모든 기업을 적자로 평가 | 영업이익률에 따라 흑자·손익분기·적자 구분 |
| `_ip_risk()` | 특허 분쟁이 없어도 소송 위험으로 평가 | 실제 특허 분쟁 여부 확인 |
| `_business_value()` | 모든 기업에 '아직 적자' 문구 사용 | 실제 수익성에 맞는 설명 생성 |
| `_financial_downside()` | 특허소송·적자 지속 위험을 고정 적용 | 기업별 실제 재무 위험만 반영 |
| `_deal_terms()` | 모든 기업에 창업자 CTO 유지 조건 적용 | 기업별 핵심인력 정보 반영 |
| `_key_talent_retention()` | 핵심 설계팀 관련 문구 고정 | 기업별 핵심인력 유지 조건 생성 |

## 3. 함수별 상세 수정 내용

### 3.1 수익성 평가 — `_profitability()`

**기존 문제**

기존에는 영업이익률이 양수여도 무조건 `concern`으로 평가하고 적자라고 설명했다.

예를 들어 브라이트셀은 영업이익률이 +6.1%인데도 적자로 표시되었다.

**수정 내용**

```python
margin = c["financials"]["operating_margin"]

if margin > 0:
    verdict = "positive"
elif margin == 0:
    verdict = "neutral"
else:
    verdict = "concern"
```

영업이익률을 기준으로 흑자·손익분기·적자를 구분하고, `finding`, `evidence`, `level`도 해당 상태에 맞춰 생성하도록 변경했다.

**검증 결과**

- 브라이트셀(+6.1%): `positive / LOW`
- 뉴로엣지(-8.2%): `concern / MEDIUM`

### 3.2 특허 분쟁 평가 — `_ip_risk()`

**기존 문제**

특허 분쟁이 없는 기업도 무조건 `concern`으로 평가했다.

브라이트셀에서는 `없음가 제기한 없음 분쟁`이라는 잘못된 문장과 소송 검증 조건까지 생성되었다.

**수정 내용**

기업 데이터의 `counterparty`, `subject`, `status`를 확인하는 조건문을 추가했다.

```python
if (
    counterparty == "없음"
    and subject == "없음"
    and "분쟁 없음" in status
):
    return _a(
        "ip_risk",
        "IP / 특허 리스크",
        "positive",
        "제공된 기업 데이터상 진행 중인 특허 분쟁 없음",
        [f"특허 분쟁 상태: {status}"],
        level="LOW",
    )
```

분쟁이 없는 경우에는 긍정 평가와 함께 소송 검증 조건을 제거하고, 실제 분쟁이 있는 경우에는 기존 위험 평가를 유지했다.

**검증 결과**

- 브라이트셀: `positive / LOW`, 소송 검증 조건 없음
- 뉴로엣지: `concern / MEDIUM`, 코어NPU 소송 검증 조건 유지

### 3.3 사업 가치 평가 — `_business_value()`

**기존 문제**

사업 가치 평가의 근거에 `(아직 적자)`라는 문구가 고정되어 있었다.

```python
f"영업이익률 {_pct(f['operating_margin'])} (아직 적자)"
```

**수정 내용**

영업이익률에 따라 `profit_status`를 결정하도록 변경했다.

```python
if margin > 0:
    profit_status = "흑자"
elif margin == 0:
    profit_status = "손익분기"
else:
    profit_status = "적자"
```

평가 근거에는 다음과 같이 실제 상태를 삽입한다.

```python
f"영업이익률 {_pct(margin)} ({profit_status})"
```

**검증 결과**

- 브라이트셀: `영업이익률 6.1% (흑자)`
- 뉴로엣지: `영업이익률 -8.2% (적자)`

이번 수정에서는 사업 가치 평가의 `positive` 판정 자체는 변경하지 않았다.

### 3.4 재무적 위험 평가 — `_financial_downside()`

**기존 문제**

모든 기업에 고객 이탈, 특허소송, 적자 지속 위험을 동시에 적용했다.

```python
"최대 고객 이탈·특허소송·적자 지속이 겹칠 경우 가치 훼손 폭이 큼"
```

**수정 내용**

실제로 확인된 위험만 `risks` 리스트에 추가하도록 변경했다.

- 최대 고객 매출 비중이 40% 이상이면 고객 집중 위험 추가
- 진행 중인 특허 분쟁이 확인되면 소송 위험 추가
- 영업이익률이 음수이면 적자 지속 위험 추가
- 실제 특허 분쟁이 있을 때만 소송 검증 조건 생성
- 위험 요인에 따라 평가 설명과 근거를 동적으로 생성

**검증 결과**

| 기업 | 확인된 위험 | 평가 |
|---|---|---|
| 브라이트셀 | 고객 이탈 위험(52%) | `concern / MEDIUM` |
| 뉴로엣지 | 고객 이탈(46%)·특허소송·영업적자 | `concern / MEDIUM` |

브라이트셀은 흑자이고 특허 분쟁이 없으므로 해당 위험을 제외하되, 높은 고객 의존도에 따른 위험은 유지했다.

### 3.5 거래 조건 평가 — `_deal_terms()`

**기존 문제**

모든 기업에 창업자 CTO 및 핵심 설계팀 유지 조건을 적용했다.

**수정 내용**

기업 데이터의 `technology.core_team`을 사용하도록 변경했다.

```python
core_team = c["technology"]["core_team"]
```

```python
condition = f"{core_team} retention 조건 확보"
```

**검증 결과**

- 뉴로엣지: 창업자 CTO 중심의 핵심 설계팀 유지 조건
- 브라이트셀: 공정 개발 총괄 중심의 핵심 공정팀 유지 조건

협상 기준가격도 각각 2.3조 원, 1.5조 원으로 기업별 데이터에 맞게 생성되었다.

### 3.6 핵심인력 유지 평가 — `_key_talent_retention()`

**기존 문제**

`핵심 설계팀` 및 `창업자 CTO` 관련 설명과 조건이 고정되어 있었다.

또한 `_deal_terms()` 수정 이후에는 두 함수가 서로 다른 핵심인력 유지 조건 문자열을 반환하는 문제가 발생했다.

**수정 내용**

`technology.core_team`을 이용해 핵심인력 평가 설명과 유지 조건을 생성하도록 변경했다.

```python
core_team = c["technology"]["core_team"]
```

```python
finding = f"{core_team}이 이탈하면 인수로 얻는 기술 가치가 훼손될 수 있음"
```

```python
condition = f"{core_team} retention 조건 확보"
```

두 함수가 동일한 핵심인력 유지 조건을 생성하도록 통일했다.

기존 핵심인력 이탈 위험 수준인 `concern / HIGH`는 유지했다.

### 4.2 전체 M&A Workflow 검증

개별 함수뿐 아니라 `review_acquisition()`을 통해 실제 `companies.json`에 등록된 두 기업을 평가했다.

| 평가 항목 | 브라이트셀 | 뉴로엣지 |

| 인수가격 프리미엄 | 6.7% | 21.7% |
| 영업이익률 | +6.1%, 흑자 | -8.2%, 적자 |
| 최대 고객 의존도 | 오토원 52% | 알파모바일 46% |
| 특허 분쟁 | 진행 중인 분쟁 없음 | 코어NPU 특허소송 |

**브라이트셀의 인수 조건**

**뉴로엣지의 인수 조건**

- 인수 협상 기준가격 2.3조 원 이하
- 알파모바일 계약 지속 여부 검증
- 코어NPU 특허소송 잠재손실 검증
- 창업자 CTO 중심의 핵심 설계팀 유지 조건 확보

두 기업의 최종 권고는 동일하지만, 판단 근거와 위험 요소, 거래 조건은 실제 기업 데이터에 따라 달라지는 것을 확인했다.

## 5. 기존 시스템과의 호환성

이번 작업에서는 다음 구성 요소를 변경하지 않았다.

- `run_mna_review` Tool의 기존 입력 인터페이스
- 경영자문 Agent의 Skill 및 시스템 프롬프트
- LangGraph 기반 Agent 실행 구조
- Super Agent 및 A2A 통신
- 프론트엔드 UI

기존 Workflow 테스트는 통과했으나 실제 LLM 경영자문 Agent의 최종 자연어 응답과 팀 통합 시스템의 전체 실행까지 검증한 것은 아니다.

## 6. 남아 있는 한계

이번 오류 수정은 현재 제공된 가상 기업 데이터와 평가 규칙을 기준으로 진행했다.

따라서 다음 사항은 향후 개선이 필요하다.

1. 기업 데이터의 누락값이나 다른 특허 분쟁 표현에 대한 예외 처리
2. 평가 임계값 및 고정 평가 규칙의 타당성 검토
3. 미등록 기업에 대한 실시간 자료 수집 및 분석
4. 사용자가 변경한 인수 조건을 반영하는 What-if 시나리오 구현
5. 실제 경영자문 Agent 호출 및 팀 통합 환경에서의 검증

특히 이번 수정만으로 모든 기업에 대한 범용적인 M&A 분석이 가능한 것은 아니다.
