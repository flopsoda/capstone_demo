# 05. M&A 경영진 종합 평가 Workflow 개발 및 Agent 검증

## 1. 개발 개요

### 1.1. 개발 목적

기존 경영자문 Agent는 CEO·CFO·CTO 관점별 M&A 평가와 What-if 시나리오 분석을 지원하지만, 세 관점의 평가 결과를 하나의 경영진 종합 보고서로 통합하는 기능은 별도로 필요하였다.

이번 개발에서는 기존 M&A 평가 Workflow를 재사용하여 CEO·CFO·CTO의 평가 결과를 통합하고, 주요 위험과 인수 기회, 최종 권고 및 판단 근거를 제공하는 기능을 구현하였다.

또한 LLM이 생성한 보고서의 필수 정보 누락에 대응할 수 있도록 검증 절차를 개선하고, 실제 Agent 환경에서 신규 기능의 정상 작동 여부를 확인하였다.

### 1.2. 개발 범위

- CEO·CFO·CTO 관점별 평가 결과 통합
- 주요 위험 및 인수 기회 중복 제거
- 종합적인 인수 권고 및 판단 근거 생성
- 구조화된 평가 결과 기반 종합 보고서 작성
- LLM 보고서 검증 실패 시 대체 보고서 처리
- What-if 입력값 예외 처리 개선
- Python 자동 테스트 및 실제 LLM Tool Calling 검증

기존 LangGraph 실행 구조와 M&A 평가 함수를 활용하였으며, 다른 Agent와 프론트엔드 UI는 수정하지 않았다.

## 3. 경영진 종합 평가 Workflow 개발

### 3.1. CEO·CFO·CTO 평가 결과 통합

**파일:** `mna_executive_summary.py`

**함수:** `review_executive_summary()`

기존 `review_acquisition()`을 CEO·CFO·CTO 각각에 대해 실행하고, 반환된 평가 결과를 통합하도록 구현하였다.

**주요 처리 과정**

1. 기존 M&A 평가 함수로 CEO·CFO·CTO의 개별 평가 수행
2. Persona별 주요 평가 결과 수집
3. 중복된 위험 및 긍정 요인 통합
4. 최종 인수 권고와 선행 조건 정리
5. 경영진 종합 보고서 생성

각 Persona의 평가 결과는 `executive_reviews`에 저장하며, 기존 평가에서 제공하는 `assessments`, `positives`, `concerns` 등을 활용한다.

이를 통해 사용자는 개별 Persona를 각각 호출하지 않고 하나의 종합 평가 요청으로 세 관점의 분석 결과를 확인할 수 있다.

### 3.2. 주요 위험 통합

**함수:** `extract_key_risks()`

CEO·CFO·CTO의 평가 항목 중 우려 사항을 추출하고 동일한 평가 기준을 가진 위험을 통합하도록 구현하였다.

**주요 기능**

- `verdict="concern"`인 평가 항목 추출
- `criterion` 기준 중복 위험 제거
- 동일 위험을 제시한 Persona 정보 기록
- 서로 다른 위험 등급이 존재할 경우 높은 등급 우선 적용
- 위험 등급에 따른 결과 정렬

위험 등급의 우선순위는 `HIGH → MEDIUM → LOW`로 설정하였다.

이를 통해 동일한 위험이 여러 Persona 평가에 중복되어 나타나는 문제를 줄이고, 중요한 위험부터 확인할 수 있도록 하였다.

### 3.3. 주요 인수 기회 통합

**함수:** `extract_key_opportunities()`

각 Persona의 평가 결과 중 긍정적인 항목을 추출하고 동일한 평가 기준을 가진 항목을 통합하도록 구현하였다.

주요 분석 대상은 전략적 적합성, 시장 진입 기간 단축, 사업 성장성 및 기술적 경쟁력 등이다.

각 긍정 요인에는 해당 평가를 제시한 Persona 정보를 함께 포함하여 결과의 근거를 구분할 수 있도록 하였다.

### 3.4. 최종 의사결정 근거 생성

**함수:** `build_decision_rationale()`

종합 평가 결과의 긍정 요인, 주요 위험 및 인수 조건을 바탕으로 최종 의사결정 근거를 정리하도록 구현하였다.

| 반환 항목 | 내용 |
|---|---|
| `recommendation` | 최종 인수 권고 |
| `positive_factors` | 주요 긍정 요인 |
| `high_risks` | HIGH 등급 위험 |
| `required_conditions` | 인수 진행 조건 |
| `summary` | 종합적인 판단 근거 |

최종 권고만 제시하는 대신, 권고에 영향을 미치는 주요 요인과 검증해야 할 조건을 함께 제공하도록 개선하였다.

## 4. M&A 종합 보고서 생성 기능

### 4.1. 보고서 생성 구조

기존 M&A 평가 결과를 활용하여 경영진 종합 보고서를 작성하는 `verified_report`를 구현하였다.

보고서는 다음 항목으로 구성된다.

1. 기업 개요
2. 재무 및 기업가치
3. 주요 고객 및 기술
4. CEO·CFO·CTO 관점별 평가
5. 핵심 위험
6. 인수 기회
7. 인수 조건
8. 최종 권고

보고서에 사용되는 주요 재무정보와 평가 결과는 기존 Workflow의 구조화된 데이터를 기반으로 작성된다.

### 4.2. Persona별 평가 내용 반영

종합 보고서에서 CEO·CFO·CTO의 평가 결과를 구분하여 표시하도록 구현하였다.

| Persona | 주요 평가 항목 |
|---|---|
| CEO | 전략적 적합성, 사업 성장성, 시장 진입 효과 |
| CFO | 기업가치, 수익성, 고객 집중도, 재무 위험 |
| CTO | 기술 적합성, 핵심인력 유지, 특허 위험, 기술 통합 |

각 Persona의 `assessments`에 포함된 실제 판단 근거를 보고서에 반영하여, 단순한 역할 설명이 아닌 기업별 분석 결과가 출력되도록 하였다.

### 4.3. 기존 M&A Tool 연동

**파일:** `run_mna_review.py`

기존 `run_mna_review` Tool에 `persona="ALL"` 요청을 처리하는 기능을 연결하였다.

| 입력 조건 | 실행 기능 |
|---|---|
| `CEO`, `CFO`, `CTO` | 기존 개별 M&A 평가 |
| 개별 Persona + 변경 조건 | What-if 분석 |
| `ALL` | 경영진 종합 평가 |

`ALL`과 What-if 변경 조건이 동시에 전달되는 경우에는 지원하지 않는 조합임을 안내하도록 하였다.

기존 Tool 이름과 필수 입력 구조를 유지하여 Agent의 Tool Calling 방식과 호환되도록 구현하였다.

## 5. Agent 보고서 검증 기능 개선

### 5.1. LLM 보고서 사실 검증

**파일:** `advisory.py`

기존 `validate_mna_report()`를 활용하여 LLM이 작성한 종합 보고서와 M&A Tool의 실제 평가 결과를 비교하도록 하였다.

검증 항목은 다음과 같다.

- 기업명
- 매출 및 영업이익률
- 인수 요구가격
- 주요 고객 및 매출 비중
- 특허 분쟁 관련 정보
- 최종 인수 권고
- 인수 진행 조건

필수 정보가 누락된 경우 해당 항목을 확인할 수 있도록 하였다.

현재 검증 방식은 주요 데이터와 조건의 포함 여부를 확인하는 구조이며, 생성된 모든 문장의 의미적 정확성을 보장하는 것은 아니다.

### 5.2. 검증 실패 시 대체 보고서 처리

**함수:** `run_advisory_agent()`

LLM이 생성한 종합 보고서에서 필수 정보가 누락된 경우, Workflow에서 생성한 `verified_report`를 대체 보고서로 사용할 수 있도록 개선하였다.

**처리 과정**

1. `run_mna_review` 실행 결과 확인
2. 종합 평가 결과에 대해 LLM 보고서 검증
3. 검증 실패 시 `verified_report` 확인
4. 대체 보고서가 검증을 통과하면 최종 응답으로 반환
5. 대체 보고서도 검증에 실패하면 오류 반환

대체 보고서가 사용되는 경우 최종 응답 이벤트에도 검증된 보고서가 반영되도록 처리하였다.

이를 통해 LLM 응답에서 필수 정보가 누락되는 상황에 대응할 수 있도록 하였다.

### 5.3. What-if 입력값 오류 처리

**파일:** `run_mna_review.py`

잘못된 시나리오 입력값으로 `ValueError`가 발생하는 경우, 예외를 처리하고 오류 유형을 반환하도록 개선하였다.

주요 반환 항목은 다음과 같다.

```python
{
    "error": str(exc),
    "error_type": "INVALID_SCENARIO",
}
```

기존의 입력값 검증 기능을 유지하면서, Agent가 잘못된 입력으로 인한 오류를 정상적인 평가 결과와 구분할 수 있도록 하였다.

- 주요 인수 기회 추출

## 7. 실제 Ollama Cloud Agent 테스트

### 7.1. 테스트 목적

신규 개발한 종합 보고서 기능이 실제 LLM 환경에서도 호출되는지 확인하고, 기존 일반 평가 및 What-if 기능과의 호환성을 검증하였다.

테스트는 자연어 질문을 전달한 후 실제 `run_mna_review` Tool 호출 여부와 결과를 확인하는 방식으로 수행하였다.

### 7.2. CFO 일반 평가

**테스트 질문**

> 뉴로엣지 인수 타당성을 CFO 관점에서 검토해줘.

**실행 결과**

| 항목 | 결과 |
|---|---|
| Tool Calling | 1회 |
| Persona | `CFO` |
| 최종 권고 | `CONDITIONAL_PROCEED` |
| Tool 오류 | 없음 |

인수가격, 적정 기업가치, 영업이익률, 고객 집중도 및 주요 인수 조건이 정상적으로 반영되었다.

**판정:** 정상 작동.

### 7.3. CFO 복합 What-if 평가

**테스트 질문**

> 뉴로엣지를 2.2조 원에 인수하고 영업이익률이 5%, 최대 고객 매출 비중이 25%가 된다면 CFO 관점에서 기존 평가와 비교해줘.

**실행 결과**

| 항목 | 결과 |
|---|---|
| Tool Calling | 1회 |
| Persona | `CFO` |
| Mode | `what_if` |
| 최종 권고 | `CONDITIONAL_PROCEED` |
| Tool 오류 | 없음 |

세 가지 변경 조건이 모두 반영되었으며, 인수가격과 수익성 개선 및 고객 집중 위험 완화가 정상적으로 설명되었다.

특허소송과 핵심 인력 관련 잔여 위험으로 인해 최종 권고는 조건부 진행으로 유지되었다.

**판정:** 정상 작동.

### 7.4. CEO·CFO·CTO 종합 평가

**테스트 질문**

> 뉴로엣지 인수 타당성을 CEO, CFO, CTO 관점에서 종합 평가하고 보고서를 작성해줘.

**실행 결과**

| 항목 | 결과 |
|---|---|
| Tool Calling | 1회 |
| Persona | `ALL` |
| Mode | `executive_summary` |
| 최종 권고 | `CONDITIONAL_PROCEED` |
| Tool 오류 | 없음 |

생성된 보고서에서 다음 항목을 확인하였다.

- CEO·CFO·CTO별 평가 결과
- 주요 재무정보 및 기업가치
- 핵심 위험과 긍정 요인
- 인수 진행 조건 4개
- 최종 인수 권고

**판정:** 신규 종합 평가 기능의 실제 Tool Calling 및 보고서 생성 성공.

### 7.5. 테스트 결과 종합

| 테스트 항목 | Tool Calling | 결과 |
|---|---|---|
| CFO 일반 평가 | 1회 | 성공 |
| CFO 복합 What-if | 1회 | 성공 |
| 경영진 종합 평가 | 1회 | 성공 |

**실제 자연어 Agent 테스트 3개 모두 성공**

이번 테스트를 통해 기존 일반 M&A 평가와 What-if 기능을 유지하면서 신규 종합 평가 기능이 정상적으로 호출되는 것을 확인하였다.

다만 실제 웹 UI와 Super Agent를 통한 통합 실행은 아직 검증하지 않았다.

## 8. 코드 검토 및 개선 사항

이번에 수정한 경영자문 Agent 코드와 실제 실행 결과를 중심으로 개선 사항을 정리하였다.

### 8.1. LLM 응답의 판단 근거 표현 개선

**대상 파일:** `advisory.py`

실제 What-if 응답에서 다음과 같은 표현상의 문제를 확인하였다.

- 자체 개발 대비 시장 진입 기간 단축 효과와 실제 출시 시점의 구분이 불명확한 사례
- 과거 3년 매출 CAGR을 향후에도 유지할 것으로 예상하는 표현
- CFO 관점 요청에 CEO 전략 평가가 추가되는 사례

현재 보고서 검증 기능은 주요 수치와 조건의 포함 여부를 확인하지만, 이러한 설명상의 부정확성을 모두 탐지하지는 못한다.

따라서 Agent의 응답 지침을 보완하여 데이터에 근거하지 않은 미래 예측을 제한하고, 기간의 의미와 Persona별 분석 범위를 명확하게 할 필요가 있다.

### 8.2. What-if 반환 코드 정리

**대상 파일:** `run_mna_review.py`

What-if 결과를 반환하는 딕셔너리에 `query` 필드가 중복 선언되어 있는 부분을 확인하였다.

현재 확인된 실행 결과에는 문제가 없지만, 불필요한 중복이므로 추후 코드 정리 시 제거할 예정이다.

### 8.3. 보고서 검증 과정의 이벤트 처리 확인

**대상 파일:** `advisory.py`

검증이 완료되기 전까지 Agent 이벤트를 보관한 후 전달하는 구조이므로, 실제 UI에서 응답이 표시되는 방식과 스트리밍 지연 여부를 확인할 필요가 있다.

이번 테스트에서는 최종 응답 생성이 정상적으로 수행되었으나, UI 스트리밍에 대한 성능 검증은 진행하지 않았다.

**종합 평가**

현재 발견된 사항은 주요 M&A 계산 로직의 오류라기보다 응답 정확성과 코드 정리, UI 연동 과정에서 확인이 필요한 부분이다.

현재 테스트 결과만으로 공용 LangGraph 실행 구조나 다른 Agent 코드를 반드시 수정해야 할 문제는 확인되지 않았다.
